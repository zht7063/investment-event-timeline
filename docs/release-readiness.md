## 部署准备与回滚

- Node / systemd 是本次首选交付方式；不要求 Docker 验收阻塞该路径。
- `deploy/setup.sh` 已改为用户服务，路径、监听地址、端口和同步间隔可配置；先检查旧 cron，避免与新 timer 重复同步。脚本和模板尚未安装到测试机。
- `npm run backup` 使用 SQLite backup API，包含 WAL 中已提交的数据，执行完整性检查，输出文件权限为 600。已在本机实际执行成功；备份目录不进入 Git。
- `.dockerignore` 排除凭证、数据库和本地依赖；Dockerfile 补齐同步脚本、健康检查和非 root 运行。当前机器没有 Docker，镜像构建和运行尚未实测，不声称该路径已验收。
- 部署前保留当前代码、生产构建和服务配置，并备份数据库。停用旧 cron 或 timer 后再切换版本。新版本启动成功后恢复唯一一套调度。
- 回滚先停止应用及同步任务，恢复上一版代码、构建和服务配置，再重启。此次数据库变更仅增加可空字段，旧代码可忽略；只有确实需要回滚数据时才在停止所有写入后恢复备份，同时移走对应 WAL/SHM 文件，避免混用。
- 发布后检查 health、首页、来源页、导入页、无口令管理请求拒绝、浏览器主链路；重启服务后核对资料及关联仍存在。
