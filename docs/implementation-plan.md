# 投资事件情报与证据时间线项目实施计划

> 本文保留早期演示版设计。新的股票区间自动研究以 [stock-research-plan.md](stock-research-plan.md) 为准。

本项目交付一个可操作的 Web 产品，让用户围绕一个投资事件查清最初来源、事实变化、证据冲突、当前结论及关联标的。实际剩余时间约 3 小时，开发以 AI 编程为主，因此保留题目要求的全部产品能力，只删去单实例演示用不到的防御性工程，以及 3 小时内无法验证的基础设施。本文是待实施方案，不代表应用、数据接口或部署已经完成。

## 1. 范围与验收标准

目标用户是跟踪 A 股公司公告与市场信息的个人研究者。首版围绕公司事件，支持公告、新闻、研报观点和市场传闻的文本资料；不做全市场资讯平台、用户系统、持仓管理、交易或投资建议。

| 题目要求 | 产品能力 | 验收证据 |
| --- | --- | --- |
| 识别、合并、跟踪同一事件的不同来源与版本 | 导入、内容哈希去重、同 URL 新版本、候选归并、确认/撤销关联、定时同步 | 多来源资料进入同一事件；同公司不同事项不合并；重复导入不产生重复论断 |
| 区分事实、观点、推测、传闻并体现权重 | 论断级分类、来源等级、直接性、原文摘录引用 | 一篇资料可同时包含事实和观点；每条论断可定位原文 |
| 事实变化与证据冲突 | 支持、反驳、更正、替代关系及冲突卡片 | 冲突双方同时可见，不被新摘要覆盖 |
| 四类时间 | 发生、披露、抓取、来源更新时间分别存储和展示 | 缺失显示“未知”；补录的旧资料不会伪装成最新事实 |
| 更新、否认、更正、过期改变结论 | 规则重算、结论版本历史、“截至某时”回看 | 每次变化有原因和触发证据 |
| 关联关注标的 | 本地关注清单、直接/间接关联及理由、行情背景 | 不凭行业相同推断影响；行情不作为真假证据 |
| 可访问产品、仓库、README、AI 记录、测试说明 | 单实例部署、健康检查、文档 | 外网 URL 可完成主链路，重启后数据仍在 |

### 一次完整操作

用户在事件列表按关注公司筛选，打开事件详情，看到“截至何时、当前判断、仍不确定什么”。点击时间线节点查看原文摘录和来源。导入一条新公告后，系统抽取论断并给出归并候选；确认关联后状态重算，结论历史显示变化原因。关联有误时可撤销并重算，操作记录保留。

## 2. 技术方案

- TypeScript + Next.js App Router，页面与 API 在同一个项目。
- SQLite 单文件数据库。优先用 Node 内置 `node:sqlite`，手写 `schema.sql` 启动时执行，不引入 ORM 和迁移工具；若搭建时发现不可用，换 `better-sqlite3`。部署镜像用 Node 24 LTS。
- Zod 校验 API 输入和模型输出；Vitest 覆盖领域规则与入库流程；Playwright 跑一条主链路冒烟（固定模型响应）。
- 普通 CSS，不引入组件库、状态管理、向量数据库或队列。
- 模型通过一个服务端模块调用 OpenAI 兼容接口，`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY` 由环境变量配置。模型只做论断抽取、分类建议、归并候选与理由；引用校验、关联提交和状态计算由应用规则完成。资料原文只作为数据传入，不能改变系统指令或触发工具调用。

## 4. 数据模型与证据语义

| 表 | 必要字段 |
| --- | --- |
| sources | 名称、类型、来源等级、接入状态（构造/真实/未接入）、最近成功同步时间与错误 |
| documents | 来源、规范 URL 或供应商 ID、标题、转载自（来源链） |
| document_versions | 正文、内容哈希、`published_at`、`source_updated_at`、`fetched_at`、上一版本 |
| claims | 文档版本、原文摘录与位置、类别、主体/事项/对象、内容、`occurred_at` 及精度、`valid_until`、单位与口径、审核状态 |
| events | 标题、类型、主体标的、事项标识、当前结论 ID |
| event_evidence | 事件、论断、关系（支持/反驳/更正/替代）、目标论断、理由、创建与撤销时间 |
| event_instruments | 事件、标的代码与名称、直接/间接、理由、依据论断 |
| conclusions | 事件、状态、摘要、有效证据 ID、冲突与缺失项、生成时间、上一版本、变化原因 |
| sync_runs | 来源、开始/结束时间、状态、新增/重复数量、错误信息 |

关注清单存浏览器 `localStorage`，使用构造标的组合，不收集持仓。

### 四类时间

- `occurred_at`：事件实际发生时间，可为空，保留原始表述和日期精度，不把“某日”伪装成精确时刻。
- `published_at`：该资料或版本的披露时间，由来源给出。
- `fetched_at`：系统取得资料的时间，系统写入。
- `source_updated_at`：来源自己的更新时间，可为空。

存储用 ISO 8601（UTC），界面标注北京时间 UTC+8。时间线默认按披露时间，可切换发生时间；未知时间单列，不用抓取时间填充。“截至某时”视图只使用 `fetched_at` 不晚于该时点的证据，后补资料不会泄漏到早期结论。

### 类别与权重

分类对象是论断。事实表示可核验的陈述，不等于已证实；“媒体报道某人说了什么”和“该说法为真”拆成两条。来源等级：监管/交易所披露 > 当事方公告 > 可追溯媒体原始报道 > 研报或评论 > 匿名传闻，再结合是否直接针对该论断、是否被更正或过期。当事方表态不替代独立验证。转载沿来源链归并，不因数量增加权重。等级只用于排序和规则，不换算成真实性概率。

“首次来源”显示为已收录资料中最早可追溯的一条；来源链断裂时注明无法确认最初出处。

## 5. 主链路规则

1. **导入与去重**：粘贴文本并填写来源元数据。同规范 URL 或供应商 ID 视为同一文档；内容哈希相同视为重复；内容变化则追加版本。URL 只作出处链接，服务端不抓取任意 URL。
2. **抽取与校验**：模型返回结构化论断、类别、时间、标的、原文摘录和事件特征。摘录必须逐字存在于该版本正文，字段通过 Zod；校验失败的论断不进入结论。模型失败或未配置时资料保留为“待分析”，可重试或人工录入论断。
3. **事件候选**：按主体标的、事件类型、事项标识、时间窗口打分召回，模型补充理由。同公司不足以合并；事项标识一致或确定重复时自动关联，其余由用户确认或新建事件。
4. **证据关联与撤销**：关系必须指向目标论断；撤销只写撤销时间，不删除记录，之后重算。
5. **结论重算**：在一个 SQLite 事务内追加结论版本并更新当前指针；有效证据集合未变化时不新增版本。
6. **可追溯表达**：状态由规则决定，摘要由模板生成，每句绑定证据 ID。可选让模型润色，但润色结果引用的证据 ID 必须是有效证据子集，否则回退模板。
7. **持续跟踪**：`scripts/sync.ts` 由服务器 cron 定时运行，数据源页另有手动同步按钮（需 `ADMIN_TOKEN`）。两者调用同一入库逻辑，每次写 `sync_runs`；依靠去重保证重复同步不重复入库。进程级文件锁防止两次同步重叠。读取事件时检查 `valid_until`，到期无新资料也会重算。

### 结论状态

状态：`待核实 / 已有证据支持 / 存在冲突 / 已被否认 / 已失效`。数据新鲜度和接口健康单独显示，接口失败不等于事件失效。

| 输入或条件 | 行为 |
| --- | --- |
| 只有传闻或推测 | 待核实，并列出缺少的证据类型 |
| 有效的正式披露 | 支持其覆盖的论断，不扩展为整个事件属实 |
| 同一论断支持与反驳并存 | 存在冲突，列出双方内容、时间和来源，不单凭等级抹掉反证 |
| 明确否认且无有效实质支持 | 已被否认；“尚未决定”不改写为“不会发生” |
| 更正公告 | 原论断保留并标记被替代，按更正范围更新 |
| 资料中明确的有效期已过 | 已失效并显示依据；不推断事件未发生，不设统一过期天数 |
| 同步失败或数据超过新鲜度阈值 | 保留旧结论并显示截至时间与过期提示，不生成新的“正常”结论 |

## 6. 页面与接口

| 页面 | 内容 |
| --- | --- |
| 事件列表 | 搜索、关注筛选、状态筛选、最近变更、数据截至时间；空结果说明原因 |
| 事件详情 | 当前结论与不确定项、关联标的与行情背景、证据时间线（可切换时间轴）、冲突卡片、原文摘录、结论历史、“截至某时”回看 |
| 导入 | 来源与四类时间输入、正文、分析进度与预览、候选确认/新建/重试 |
| 数据源 | 接入模式、最近同步记录、错误类型、手动同步 |

状态同时用文字和颜色表达；支持键盘操作和窄屏布局；加载、空、错误、过期分别有明确提示，不用空列表代替错误。

接口：`GET /api/events`（分页筛选）、`GET /api/events/:id`（可带 `asOf`）、`POST /api/documents`、`POST /api/documents/:id/analyze`、`POST /api/associations`、`DELETE /api/associations/:id`、`POST /api/sources/:id/sync`、`POST /api/demo/reset`、`GET /api/health`（不调用付费接口）。

安全边界：写接口 Zod 校验并限制正文长度（20,000 字）；原文以纯文本渲染；错误响应带错误码，不返回堆栈和凭证；同步与重置需 `ADMIN_TOKEN`。公开实例允许访客导入，被污染时由管理员一键重置为构造数据；不做访客隔离和请求限流，README 写明这一边界。

### 外部调用的超时与重试

模型和数据源调用超时 30 秒，每次尝试记录状态码与耗时：

- `429`：等待返回的 `Retry-After`，每次新的值都重新等待，最多重试 3 次；仍为 429 则停止，界面显示限流失败。
- `5xx` 或超时：间隔 1 秒、2 秒，最多重试 2 次；仍失败则标记失败并保留原状态。
- `400/401/403`：不重试，直接显示参数、认证或权限错误。

## 7. 数据接入

扶摇和 iFinD MCP 的权限、参数、字段与授权均未验证。开工后限时 20 分钟探测：各取一个标的或一条资料，记录脱敏请求、返回字段与错误。

- 探测成功：扶摇提供标的名称、行情快照等背景；iFinD 若能返回公告/新闻，接入同步。行情不作为事件真假的证据。
- 探测失败：主链路使用人工导入和明确标记“构造演示数据”的样例，数据源页显示“未接入”及失败原因，不伪装成实时资讯。剩余时间允许时再接入。

API Key、受限全文和接口原始响应不进入仓库。

## 8. 三小时实施顺序

AI 编程可并行生成多块代码，瓶颈在验证和部署，因此按“可验证的增量”排序。

| 时间 | 内容 | 完成标准 |
| --- | --- | --- |
| 0:00–0:20 | 确认服务器与模型 Key；并行探测扶摇/iFinD；搭建 Next.js 骨架与 schema | 本地启动；知道哪些来源可用 |
| 0:20–1:00 | 种子数据、领域规则（去重、候选、四时间、权重、状态计算）及单元测试 | 种子事件链计算出正确结论和历史 |
| 1:00–1:45 | 列表、详情、导入页面；AI 抽取与引用校验；关联与撤销 | 浏览器完成导入→分析→归并→详情→原文 |
| 1:45–2:15 | 截至某时、过期、数据源页、同步与 cron 脚本、错误状态、关注筛选、行情背景 | 否认与更正改变结论；失败可见 |
| 2:15–2:40 | 部署（Docker 或 Node 直接运行，数据目录持久化），外网验收；同时补 Playwright 冒烟 | URL 可操作，重启后数据仍在 |
| 2:40–3:00 | README、`docs/ai-usage.md`、`docs/testing.md`，修复问题 | 交付物齐全，记录为真实结果 |

服务器信息必须在第一个时段拿到，否则部署是最大风险。超时时依次压缩：视觉细节、Playwright、模型润色摘要、真实数据源同步；不削减引用、冲突、四类时间、结论历史和失败提示。

## 9. 测试与演示数据

构造虚拟公司事件链：传闻 → 新闻转述 → 正式公告 → 局部更正 → 否认某一分支 → 有效期结束。另加同公司不同事项、不同公司同名项目两个干扰样例。所有名称和数字显式标为构造数据。

| 类别 | 最少覆盖 |
| --- | --- |
| 主链路 | 四分类；同 URL 新版本；重复导入幂等；转载不加权；支持/冲突/否认/更正/过期；撤销后重算；截至某时不读未来证据；同公司不同事项不合并；单位与口径不混算 |
| 数据缺失与接口失败 | 缺失时间显示未知；模型未配置、超时、非法 JSON、伪造引用；数据源认证失败与 429；均保留旧状态并显示失败 |
| 极端与合规 | 空正文、超长正文、HTML 脚本原样显示、提示注入不改变分类、未授权同步被拒、输出不含涨跌预测和买卖建议 |
| 浏览器 | 导入→归并→详情；新增否认→结论变化→回看历史；关注筛选；刷新后数据仍在 |

模型相关测试使用固定响应夹具；真实模型与数据源冒烟单独记录，不把模拟通过当作真实接入成功。`docs/testing.md` 记录命令、日期、预期、实际与未解决问题。`docs/ai-usage.md` 从开发开始记录 AI 工具、参与环节、人工校验和纠正内容，尚未发生的修正不编造。

## 10. 部署与交付

单实例部署：Docker（Node 24 镜像，挂载 `data/`）或服务器直接 `npm run build && npm start` 配合进程守护；有域名时加反向代理与 HTTPS；cron 调用 `scripts/sync.ts`。部署前复制一份数据库文件作为备份。环境变量：`DATABASE_PATH`、`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`、`ADMIN_TOKEN`，以及探测成功的数据源凭证。

交付清单：

- 可访问并可操作的 Web URL。
- 源码仓库与交付 commit（配置远端前不宣称已发布）。
- README：启动方式、环境变量、产品选择、AI 角色、数据来源、已知边界、未做事项。
- AI 使用与验证记录、测试说明。
- 可选 60–180 秒演示视频，必交项完成后再做。
