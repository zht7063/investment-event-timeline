# 题目 08｜投资事件情报与证据时间线：测试说明

本说明对应[题目要求](title-投资事件情报与证据时间线.md)，优先覆盖题目明确要求的主链路、数据缺失／接口失败、极端或合规边界场景，最后补充三项关键测试。每项给出操作和通过标准，便于按项验收。

产品入口：[投资事件情报与证据时间线](https://timeline.tianyubai.cn)。

## 一、测试准备

- 页面验收优先使用[构造演示事件](https://timeline.tianyubai.cn/events?q=构造演示)和[研究记录](https://timeline.tianyubai.cn/research)，全部假数据均标注“构造演示”，不代表真实证券结论。
- 导入、故障注入、重试、撤销和删除测试在本地隔离数据库执行，避免影响测试服务器的共享数据。准备同一事件的传闻、公告、反驳、更正及到期资料，另外准备不同公司、不同事项和不同报告期资料。
- 接口与模型异常使用本地替身模拟；真实来源验证另行记录标的、披露区间、时间和覆盖限制。构造数据和替身测试不能证明真实接口可用或资料覆盖完整。

## 二、题目要求的测试项目

### 1. 主链路：识别、合并和跟踪同一事件

| 编号 | 测试项目 | 操作／输入 | 通过标准 |
| --- | --- | --- | --- |
| M01 | 完成核心操作链路 | 导入一份传闻，分析并建立事件；再导入同事项公告，确认归并；打开详情和历史记录。 | 资料、论断和事件均可查询；两份资料关联同一事件；新增证据触发结论更新，并保留变更原因与历史版本。 |
| M02 | 同一事件的多来源与版本 | 重复导入相同 URL、相同内容，再以同 URL 导入变更内容；补充另一来源的同事项资料。 | 重复内容不重复入库；变更内容保留为新版本；不同来源保留各自出处，原版本不被覆盖。 |
| M03 | 最初来源与转载链 | 查看“转载与观点”案例，沿来源链查看匿名帖及媒体转载。 | 能找到已收录资料中最早可追溯的来源；转载归于同一来源链，不因转载数量增加而成为多个独立证据。不得将其宣称为全网首发。 |
| M04 | 事实、观点、推测与传闻 | 分别导入四类论断，查看分类、来源等级及结论；增加多篇传闻转载。 | 四类论断明确区分；来源等级和权重可辨认；观点、推测和传闻不能仅因数量多而成为有事实支持的结论，权重不解释为真实性概率。 |
| M05 | 四类时间 | 导入发生时间、披露时间、抓取时间、来源更新时间各不相同的资料；再输入仅日期和时间未知的资料。 | 各时间按各自含义存储和展示；日期精度保留；未知时间不补成抓取时间，不虚构具体时分秒。 |
| M06 | 更新与支持 | 先关联未获证实的传闻，再新增明确支持该论断的可追溯事实证据；查看“有证据支持”案例。 | 结论随有效证据重算；仅支持证据明确覆盖的事实，不把“方案通过”写成“已经实施”。 |
| M07 | 证据冲突 | 查看“存在冲突”案例：交易双方分别披露 60% 与 51% 的股权比例。 | 支持与反驳同时保留，结论标记存在冲突；可展开双方原文和来源，不单凭来源等级抹去反证。 |
| M08 | 否认 | 查看“已否认”案例：匿名重组传闻后出现公司澄清公告。 | 传闻被明确关联的事实证据否认，当前状态为已否认；原传闻和否认依据均可追溯。 |
| M09 | 更正与替代 | 查看“更正与历史”案例：合同金额由 10 亿元更正为 1 亿元；在隔离环境补充替代旧方案的新公告。 | 更正／替代明确指向旧论断；当前结论使用有效新证据，旧值保留在历史记录中，不与新值同时当作有效事实。 |
| M10 | 过期 | 查看“已失效”案例；在隔离环境分别查询有效期前后，并增加到期后的实质更新。 | 有效期到达且无后续实质更新时显示已失效；新增事实后重新计算，不能永远停留在旧状态。 |
| M11 | 与关注标的的关系 | 在事件详情查看直接、间接关联及依据；将对应标的加入关注清单，使用关注筛选。 | 直接主体与间接受影响标的可区分，关联理由可查；筛选结果与关注清单一致；行情背景不作为事件证据。 |
| M12 | 结论回到原始证据 | 从结论定位原文摘录、资料来源、披露／收录时点及金额单位、统计口径。 | 摘录逐字存在于收录文本，引用属于当前事件；单位与口径保留，缺失时明确提示。仅有片段／摘要时不声称已核验全文。 |

### 2. 数据缺失与接口失败

| 编号 | 测试项目 | 操作／输入 | 通过标准 |
| --- | --- | --- | --- |
| D01 | 无证据、零结果与字段缺失 | 查看“零结果”研究；创建无关联证据事件；导入缺少披露时间、金额单位或统计口径的资料。 | 正常零结果与失败可区分；无证据时保持待核实；未知字段不编造，不生成看似完整的正常结论。 |
| D02 | 数据源失败与覆盖受限 | 用替身模拟连接超时、401／403、429、5xx、业务错误、格式错误及分页预算耗尽。 | 明确展示失败或覆盖受限及原因，已收录内容保留；失败不显示为“查询完成且无资料”。瞬时错误按策略有限重试，认证失败不盲目重试，预算耗尽不解释为已检索穷尽。 |
| D03 | 模型分析失败 | 模拟未配置模型、非 JSON、非法分类／日期及不在原文中的引用；查看“覆盖受限与分析失败”案例。 | 原资料保留并显示失败或校验拒绝原因；非法引用不进入有效论断；允许重试失败部分，不能用编造分析填补空缺。 |
| D04 | 关系核验失败 | 让资料分析成功，但模拟支持／反驳关系核验失败。 | 资料和摘录仍可查，核验状态及失败原因明确；未完成核验的结果保持初步／待核实，不冒充已完成核验。 |

### 3. 极端或合规边界

| 编号 | 测试项目 | 操作／输入 | 通过标准 |
| --- | --- | --- | --- |
| B01 | 错误归并边界 | 输入同公司不同事项、不同公司同名项目、同事项不同报告期，以及金额单位／统计口径不同的资料。 | 不凭公司名或标题相似就合并；归并依据不足时保持独立或要求确认；不跨单位、口径强行比较并制造冲突。 |
| B02 | 历史时点边界 | 在人工事件“截至某时”视图查询公告抓取前后；补录披露早但抓取晚的资料，或在之后撤销证据。 | 历史结论排除当时尚未抓取／关联的证据；晚补资料不泄漏到早期视图，之后的撤销不改写撤销前视图。自动事项按各研究区间查看，不冒充同一种历史回看能力。 |
| B03 | 输入与处理上限 | 输入空正文、非法证券代码、无效／颠倒／未来日期及超过 366 个自然日的研究区间；模拟重复分页游标。 | 无效请求给出清晰提示，不创建异常任务；处理预算有限，重复游标不能导致无限请求。 |
| B04 | 投资表达与不确定性 | 检查事件摘要、研究报告、来源提示及行情背景；输入“必涨”“保证收益”“立即买入”等材料。 | 产品自身结论不输出确定性涨跌预测、收益承诺或直接买卖建议；来源中此类表述保持引用和类别标识，不转述为产品承诺；事实、推断和不确定信息清晰区分。 |
| B05 | 凭证、隐私与受限数据 | 检查待提交仓库、README、日志样例及演示资料；检查构造数据标识和管理接口鉴权。 | 不提交 API Key、用户隐私或受限数据；涉及用户画像／持仓时采用匿名或构造数据；管理接口拒绝无效口令。当前公开研究记录共享可见，不将其宣称为用户私密空间。 |

## 三、补充的重要测试项目

| 编号 | 测试项目 | 操作／输入 | 通过标准 |
| --- | --- | --- | --- |
| S01 | 逐步结果与取消后可见性 | 研究处理中打开事件库和资料库；取消任务并刷新，检查待分析、失败和日期未知资料。 | 收录即可查询，已提取事项不必等待任务结束；取消保留已有成果，迟到的后台结果不得继续写入。 |
| S02 | 删除与持久化 | 在隔离数据库创建共享资料的两条研究；删除其中一条；重启服务，并执行备份恢复核对。 | 只删除目标研究及其独占内容，共享资料和人工事件保留；重启不丢数据，恢复副本完整且与备份时一致。 |
| S03 | 页面可实际操作 | 桌面及 375px 手机宽度下打开首页、事件／资料列表、详情、导入和来源页；操作搜索、筛选、分页、原文展开并刷新。 | 主要操作可完成，刷新不报错；关键内容和按钮不被遮挡；筛选、分页与详情数据一致。 |

## 四、执行方式与结果记录

本地要求 Node.js 24+，安装依赖并准备独立测试环境：

```bash
npm ci
npm test
npm run typecheck
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
```

默认端到端测试启动独立服务和临时数据库，使用供应商／模型替身。不要将包含写操作的完整测试套件通过 `E2E_BASE_URL` 指向共享测试服务器。

主要自动化用例位置：

| 范围 | 现有测试文件 |
| --- | --- |
| 结论状态、来源链、时间、归并与引用校验 | `tests/unit/conclusion.test.ts`、`time.test.ts`、`matching.test.ts`、`ai.test.ts` |
| 导入、关联、撤销、历史回看及单位口径 | `tests/integration/ingest.test.ts`、`seed.test.ts` |
| 数据源异常、同步及自动研究 | `tests/unit/http.test.ts`、`connectors.test.ts`；`tests/integration/sync.test.ts`、`research.test.ts` |
| 资料可见性、跨研究归并与删除 | `tests/integration/library.test.ts` |
| 浏览器主链路及基本可用性 | `tests/e2e/` |

以上文件是执行入口，不代表表中每个场景均已自动化；投资表达、秘密泄露检查和真实接口覆盖限制仍需专项人工复核。

逐项记录：**用例编号、代码版本／环境、执行时间、输入或夹具、实际结果、通过／失败／未执行、证据位置**。必测项失败应记录原因并修复后复测，不能用构造案例页面可访问替代真实接口或完整交互验收。
